# Posts — тестовое задание

Next.js (App Router) + TypeScript приложение: список постов из
[JSONPlaceholder](https://jsonplaceholder.typicode.com/) и форма создания
нового поста через Server Action с валидацией Zod.

## Стек

- Next.js 16 (App Router), React 19
- TypeScript (strict)
- Tailwind CSS 4
- Zod — валидация формы на сервере

## Запуск

```bash
npm install
npm run dev
```

Откройте http://localhost:3000.

`npm run build` — продакшн-сборка, `npm run lint` — ESLint.

## Структура

```
app/
  page.tsx        # страница: форма + список (dynamic, т.к. дергаем внешний API)
  actions.ts       # Server Action createPost (валидация Zod, fetch к JSONPlaceholder)
  layout.tsx
components/
  post-list.tsx    # async Server Component — грузит и рендерит список постов
  post-form.tsx     # Client Component — форма, useActionState, локальный стейт добавленных постов
lib/
  validation.ts    # схема Zod
  types.ts         # тип Post
```

## Архитектурные решения

- **Список постов** — асинхронный Server Component (`PostList`), данные
  запрашиваются на сервере, на клиент уходит готовый HTML. Обёрнут в
  `Suspense` со скелетоном на время загрузки.
- **Форма** — Client Component, потому что нужен интерактивный стейт
  (ошибки валидации, состояние `pending`, локально показанные черновики).
  Сама отправка идёт через Server Action (`useActionState` + `formAction`),
  без ручного `fetch`/`onSubmit`.
- **Валидация** — Zod-схема (`lib/validation.ts`) используется в Server
  Action на сервере: это единственный источник правды, поэтому проверка не
  дублируется на клиенте, а читаемые ошибки прилетают через `state.errors`
  и рендерятся под нужными полями.
- **Особенность JSONPlaceholder**: этот API не сохраняет данные по-настоящему
  — `POST /posts` возвращает "созданный" объект, но следующий `GET /posts`
  его не вернёт. Чтобы демо было осмысленным, `createPost` возвращает
  реальный объект из ответа API, и форма показывает его отдельным блоком
  "локально добавленные посты", честно объясняя пользователю, почему они не
  попадают в общий список ниже. Это сознательное решение, а не баг: в
  реальном бэкенде `revalidatePath("/")` в actions.ts было бы достаточно.
- Страница помечена `export const dynamic = "force-dynamic"`, так как
  контент зависит от внешнего API и на странице есть Server Action —
  статическая генерация на этапе сборки здесь не нужна.

## Какой код сгенерирован с помощью AI и как я его проверял

Тестовое делалось с помощью Claude (в агентном режиме, с доступом к
терминалу и файловой системе).

### Сгенерировано AI и оставлено как есть (после проверки)

- **Скелет проекта** — `create-next-app` с флагами TypeScript/Tailwind/App
  Router. Не код в смысле логики, но набор флагов подобран и проверен
  (`package.json`, версии зависимостей).
- **`lib/validation.ts`** — Zod-схема. AI предложил границы (min/max длины,
  диапазон `userId` 1–10 под JSONPlaceholder). Проверял вручную: прогонял
  через `npx tsc --noEmit`, руками отправлял пустую форму и слишком
  короткий текст — убедился, что ошибки приходят по нужным полям и с
  понятным текстом.
- **`components/post-list.tsx`** — базовая структура async Server
  Component с `fetch` и `next: { revalidate: 60 }`. Проверил, что это
  действительно Server Component (нет `"use client"`, нет хуков), что при
  сборке (`npm run build`) роут помечается как ожидаемый, и что при
  недоступном API компонент кидает понятную ошибку, а не падает молча.
- **Tailwind-разметка** (карточки, форма) — AI предложил классы и сетку
  `sm:grid-cols-2`. Проверял визуально, руками менял ширину вьюпорта,
  убедился, что нет переполнений и что focus-состояния полей видны.

### Сделано вручную

  1. `components/post-form.tsx` первый вариант от AI не учитывал, что
  JSONPlaceholder не персистит данные, и ожидал, что новый пост появится в
  списке после `revalidatePath`. Я проверил это руками и переделал
  логику: `createPost` возвращает созданный объект в `state.post`, а форма
  через `useEffect` добавляет его в отдельный локальный список с явной
  пометкой "черновик", вместо того чтобы полагаться на ревалидацию. Также
  вручную добавил `useRef` (`lastHandledState`), чтобы `useEffect` не
  задублировал пост при повторном рендере состояния. В первой версии AI
  этого не было, и пост мог задваиваться при лишнем срабатывании эффекта.
  2. `app/actions.ts` обработку ошибок AI изначально сделал в виде
  голого `catch` без разделения на "ошибка валидации" и "ошибка сети/API".
  Разделил на `errors` (по полям, из Zod) и `message` (общая ошибка,
  например недоступность JSONPlaceholder), чтобы UI мог их различать.
  3. Решение о `force-dynamic` при первой сборке (`npm run build`)
  Next.js пытался статически пререндерить `/` и падал на сетевом запросе.
  Определил причину (недоступность внешнего API в момент сборки в
  этой среде) и добавил `export const dynamic = "force-dynamic"` на
  странице.
  4. Удаление `next/font/google` исходный шаблон `create-next-app`
  подключал шрифт Geist через Google Fonts. В окружении, где собирался
  проект, нет доступа к `fonts.googleapis.com`, сборка падала. Заменил на
  системный font-stack в `globals.css` вручную.
  5. Поле "ID автора" → "Имя автора". Изначально в форме было поле ID.
  Вручную поменял на имя, а сам ID остался "зашит" внутри. В форме больше не спрашиваем
  числовой ID. Пользователь вводит своё имя (`authorName`).
  Сам `userId`, которого требует JSONPlaceholder для `POST /posts`,
  генерируется автоматически на сервере в `createPost` через
  `crypto.randomInt(1, 11)` (встроенный модуль `node:crypto`, а не
  `Math.random`, чтобы генерация была криптографически случайной). Поле
  осталось "внутри" оно кладётся в объект `Post` и уходит в запрос к
  API, но нигде не рендерится: карточка черновика показывает
  `post.authorName`, а не `post.userId`. Правки: `lib/validation.ts`
  (схема Zod), `lib/types.ts` (добавлено опциональное поле `authorName`),
  `app/actions.ts` (генерация `userId`, обновлённая форма ошибок
  `title | body | authorName`), `components/post-form.tsx` (новое поле
  ввода вместо числового).
  6. Плохо видимый заголовок "Посты". Причина: в `globals.css` был
  `@media (prefers-color-scheme: dark)` блок, переключавший фон на почти
  чёрный (`#0a0a0a`), а заголовок в `app/page.tsx` использует
  захардкоженный класс `text-neutral-900` (тёмно-серый), который в тёмном
  режиме ОС становился почти нечитаемым на таком фоне. Поскольку
  переключателя темы и тёмной палитры для текста в приложении нет, самое
  надёжное решение не переключать фон автоматически. 
  Убрал `@media (prefers-color-scheme: dark)` и сделал фон постоянно светлым, но
  не белым, чтобы страница выглядела мягче. Правка только в `app/globals.css`.
  7. Runtime-ошибка `A "use server" file can only export async functions,
  found object. Причина: app/actions.ts помечен "use server"`, а из
  него, помимо самой Server Action `createPost`, экспортировался обычный
  объект `initialCreatePostState`. Объект нужен был только
  клиентскому компоненту как начальное значение для `useActionState`, так
  что вынес его из `actions.ts` прямо в `components/post-form.tsx` как
  локальную константу, а из `actions.ts` теперь импортируется только тип
  `CreatePostState`. Правки: `app/actions.ts` (убран экспорт объекта),
  `components/post-form.tsx` (объект объявлен на месте).
